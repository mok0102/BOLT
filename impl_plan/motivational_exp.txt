============================================================
OVERALL SCIENTIFIC MOTIVATION
============================================================

ORPT studies learned initialization for repeated Bayesian optimization.

We want three Branin motivational experiments:

A. Where should cross-task knowledge enter BO?
B. Does standalone point quality agree with downstream initialization quality?
C. If we learn an initializer, what training signal should it optimize?

These three experiments should form a coherent argument:

A:
Cross-task experience can be transferred through different interfaces
(e.g., surrogate transfer vs. learned initialization).

B:
Even within learned initialization, a candidate that is good by its
standalone objective value need not be the candidate that leads to a better
downstream BO outcome.

C:
We therefore test whether training an initializer from downstream rollout
outcomes is more appropriate than simpler learned-initialization objectives.

Do NOT frame the entire experiment as "BOLT vs ORPT".
BOLT / Top-K imitation is one relevant learned-initializer baseline.

EXPERIMENT B
DOES STANDALONE POINT QUALITY AGREE WITH DOWNSTREAM UTILITY?
============================================================

Scientific question:

"How does the ranking induced by standalone candidate quality differ from
the ranking induced by downstream BO outcomes?"

This is NOT primarily a model-comparison experiment.
It tests whether the proxy used to identify a "good candidate" is aligned
with the quantity that matters after BO continues.

For candidate pair (x_i, x_j), define:

    Delta_0
      = standalone utility difference

and, using MATCHED base initialization pools A_r,

    Delta_h
      = average_r [
          U_h(A_r ∪ {x_i}) - U_h(A_r ∪ {x_j})
        ]

The two pools in each matched comparison must differ in exactly one candidate.
Use identical base sets and appropriately controlled BO randomness for both
members of the pair.

Evaluate horizons:

    h in {1, 2, 3, 5, 10, 20, 50}

Compute:

    reversal_rate(h)
      = P(sign(Delta_0) != sign(Delta_h))

Handle near-ties explicitly.
Do not let tiny numerical differences count as meaningful reversals.
Reuse the existing ORPT reliability / comparison criterion if appropriate,
and additionally report how results change with and without reliability
filtering.

EXPERIMENT C
WHAT SHOULD A LEARNED INITIALIZER OPTIMIZE?
============================================================

Scientific question:

"Given that initialization is learned across tasks, which supervision signal
produces initialization that is most useful to downstream BO?"

This experiment must separate MODEL CAPACITY from TRAINING SIGNAL as much as
possible.

Evaluate:

1. Random initialization
   - no learned transfer

2. Prior-best reuse
   - reuse / transfer best solutions from previous tasks using a reasonable
     task-independent rule
   - document exact construction

3. Context -> optimum regression
   - simple non-LLM learned initializer using training pairs
       (task context t, best/optimal x)
   - use a small, standard model
   - this tests whether the low-dimensional Branin task can simply be solved
     by direct cross-task regression
   - keep implementation deliberately simple and document it

4. Top-K SFT / BOLT
   - supervised imitation of individually high-performing candidates

5. H=0 preference tuning
   - SAME reference model / preference-learning pipeline as ORPT
   - preferences determined only by standalone objective values
   - no downstream BO rollout used to label preferences

6. ORPT, H=1
   - identical preference-learning pipeline except preferences use
     downstream rollout outcomes

If existing H=2 or H=3 trained models already exist and are reproducible,
evaluate them as secondary variants, but do not make the main plot unreadable.

CRITICAL CONTROL:
For Top-K SFT, H=0 preference tuning, and H>0 ORPT:
- use the same base model family
- same training tasks
- same test tasks
- same proposal budget
- same downstream BO
- same decoding/evaluation protocol
- avoid changing anything other than the learning signal unless required
  by the method itself
